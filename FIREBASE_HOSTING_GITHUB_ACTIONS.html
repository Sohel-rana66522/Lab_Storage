Publish the Client Portal with Firebase Hosting + GitHub Actions

Every push to main builds the portal and deploys it to https://ilet-lab-d1712.web.app. Every pull request gets a temporary preview link.

1Add the files to your project

From the downloaded folder, copy these into your project root (the folder with pubspec.yaml):

  • .github/workflows/firebase-hosting-merge.yml — deploys to live on push to main
  • .github/workflows/firebase-hosting-pull-request.yml — preview URL for each pull request
  • firebase.json — replaces yours; it adds the hosting section (serves build/web, single-page rewrite so refreshing /cart works). Your Firestore and Flutter settings are kept.

Make sure the portal code (lib/client/, lib/main_client.dart) and lib/firebase_options.dart are committed, because GitHub builds from the repository.

2Create the Firebase deploy key (one command)

Install the Firebase CLI and log in, then from your project root run:

npm install -g firebase-tools
firebase login
firebase init hosting:github

Answer the prompts:

  • Project: ilet-lab-d1712
  • GitHub repository: Sohel-rana66522/Lab_Storage
  • Set up a build script? No (the workflow files already build it)
  • Deploy on merge? Yes, branch main
  • If it asks to overwrite the workflow files, answer No so it keeps mine.

This creates a service account and saves it in your GitHub repo as the secret FIREBASE_SERVICE_ACCOUNT_ILET_LAB_D1712, which is the name the workflows use. Check under GitHub → Settings → Secrets and variables → Actions.

If the command fails, create the key by hand: Firebase Console → Project settings → Service accounts → Generate new private key. Add the JSON file's full contents as a repository secret named FIREBASE_SERVICE_ACCOUNT_ILET_LAB_D1712. Never commit that JSON file.

3Check Firebase Console settings

  • Hosting: open Build → Hosting and click Get started once if the site isn't enabled yet.
  • Authentication → Sign-in method: Anonymous must be enabled, or the portal can't read data.
  • Authentication → Settings → Authorized domains: ilet-lab-d1712.web.app is there by default. Add your own domain here if you connect one.
  • Firestore → Rules: publish the new firestore.rules from the client portal zip.

4Push and watch it deploy

git add .
git commit -m "Add Firebase Hosting deploy workflows"
git push origin main

Open the repo's Actions tab. When the run turns green, the portal is live at https://ilet-lab-d1712.web.app. Each run takes a few minutes.

Good to know

  • Only the portal is published. The laboratory/admin app (lib/main.dart) is not deployed by these workflows.
  • The workflow runs flutter test before deploying, so a failing test blocks the deploy. Delete that step if you don't want this.
  • If your default branch is master and not main, change branches: [main] in the merge workflow.
  • Rules are not deployed by these workflows. Publish firestore.rules from the console or with firebase deploy --only firestore:rules.
